Como usar a API

Endereço baseTodas as rotas de negócio ficam sob /api/v1. No navegador, o site repassa /api/v1/* para a API (rewrites do Next.js), então o endereço é o do próprio site. Localmente: API em http://localhost:8000, documentação interativa em /docs.
FormatoJSON em UTF-8, nos dois sentidos. Fotos vão em multipart/form-data. Datas em ISO 8601 (UTC); a tela mostra no fuso de Manaus (RNF03).
AutenticaçãoPOST /api/v1/auth/login cria a sessão e grava o cookie siga_sessao (httponly; Secure em produção). O token também pode ir no cabeçalho Authorization: Bearer <token>. A sessão expira após 60 minutos sem uso e é renovada a cada requisição (RBN01.06).
AutorizaçãoCada rota exige um perfil (aluno, orientador, professor da disciplina, coordenador, membro da banca) e o vínculo com o registro (RN07). Sem o perfil: 403. Sem vínculo com o registro: 404, para não revelar que ele existe.
Regras gerais de respostaToda rota que exige login responde 401 sem sessão válida. Toda rota com corpo responde 400 quando o corpo é inválido (o padrão 422 do FastAPI foi trocado por 400, como pedem as fichas). A tabela de cada rota mostra os códigos que ela devolveu na suíte de testes.

Formato dos erros

Todo erro devolve um objeto JSON com detail (mensagem pronta para a tela) e, quando cabe, mais campos (backend/app/erros.py):

CampoQuando apareceExemplo
detailsempre"Confira os campos destacados."
campos400: mensagem por campo{"email": "Campo obrigatório."}
campo409: campo duplicado"email"
criterios422: senha fora do padrão[{"descricao": "Uma letra maiúscula"}]
motivolink inválido ou cadastro bloqueado"expirado", "usado", "sem_matricula", "duplicado", "nao_editavel"
campos_pendentes422 na submissão do TCC["Aguarde o orientador aceitar a orientação."]

204Sucesso, sem conteúdo.
